# 작업 기록 - PyAV 채널 정규화와 FFmpeg fallback

- 일시: 2026-11-03 (Asia/Seoul)
- 작업 유형: 전사 오류 수정

## 변경

- PyAV를 독립 프로세스에서 우선 실행하고 입력 프레임의 채널·형식·샘플레이트가 바뀌면 기존 FIFO와 리샘플러를 flush한 뒤 교체한다. 각 구간을 16kHz 모노로 변환해 이어 붙인다.
- PyAV 오류, 비정상 종료, 잘못된 출력이 발생하면 기존 FFmpeg 디코더로 다시 처리한다.
- worker가 종료되면 자식 프로세스의 감시 파이프가 닫혀 디코더도 종료된다.
- 사용된 경로를 STT sidecar의 `audio_decode_backend`에 기록하고, 재전사는 디코딩 결과를 재사용한다.

## 검증

- 전체 테스트: 407 passed, 1 skipped, 기존 Ollama 반환값 경고 2개. 추가 다중 채널 전환 테스트 후 관련 테스트 9개 통과.
- PyAV 정상 처리, 강제 비정상 종료 시 FFmpeg fallback, 부모 종료 시 자식 종료, 합성 스테레오→모노→스테레오 입력의 샘플 수 및 음성 보존을 검증했다.
- 관리형 Python 3.11 / PyAV 18.0.0에서 실제 녹음의 일정 채널 60초와 충돌했던 채널 변경 120초 구간 모두 PyAV로 성공했다.
- 채널 변경 120초 구간의 PyAV 출력은 입력 프레임에서 계산한 16kHz 샘플 수 1,920,016개와 일치했다. FFmpeg 출력은 1,919,999개이며, 17개 샘플 차이를 보정하면 전환 후 비교한 두 구간의 파형 상관계수는 각각 1.0이다.
- `git diff --check` 통과. 기존 사용자 파일은 변경하지 않았다.

## 제한

- PyAV 격리 프로세스와 임시 float32 파일에 추가 시간·메모리·디스크 공간이 필요하다.
- 실제 전체 강의 전사와 설치된 앱의 재빌드는 수행하지 않았다.
