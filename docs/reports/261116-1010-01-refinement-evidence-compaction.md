# 작업 기록 - 정제 ASR 본문 복제와 메타데이터 과다 입력 수정

- 일시: 2026-11-16 (Asia/Seoul)
- 작성자: Codex
- 작업 유형: 버그 수정 / 사용량 재조사

## 관찰

- 실행 중인 앱은 0.1.16이며 설치본의 Gemini add-on 소스 두 파일이 저장소와 일치했다.
- 실제 정제 응답 로그 네 건의 입력 토큰은 9,480 / 9,480 / 8,246 / 8,316이다.
- 합계 35,522이며 요청별 세션 식별자가 없어 네 건이 같은 작업인지 단정할 수 없다.
  같은 토큰 수가 반복됐다는 사실만으로 같은 요청의 중복 실행이라고 판단하지 않는다.
- 이전 버전의 같은 작업 실측 기준이 없어 전보다 사용량이 늘었다고 확정할 수 없다.
- 0.1.16은 구간 범위만 줄였고, 본문 복제 및 최대 80개 segment별 JSON key·긴 실수
  표현 반복을 남겼다. 실제 자료는 4천 자 본문에 약 1.2만~1.5만 자 evidence가 붙는다.

## 수정

- 중복 본문 대신 chunk 기준 문자 위치·시작 시간·confidence 배열을 전달한다.
- LLM 입력 숫자만 소수 셋째 자리까지 줄이고 raw metadata를 변경하지 않는다.
- 앞뒤 각 240자 문맥, 용어집, 현재 문맥과 다른 ASR 후보를 유지한다.
- 매 요청의 본문·보조 문맥·system 문자 수를 토큰 사용량과 함께 로그에 남긴다.
- 설치된 앱의 코드나 서명은 직접 변경하지 않았다.

## 검증

- 관련 테스트 40개 통과. 짧고 촘촘한 segment, 대형 segment, 중복 ASR 후보,
  원문 위치 연결 실패, 후반 구간, 숫자 정밀도와 로그 내용 비노출을 검증했다.
- 실제 전사문을 로컬에서 요청으로 재구성해 문자 수만 비교했다(API 전송 없음).
  - 본문 19,525자: 입력 92,427 → 45,617자(50.6% 감소).
  - 본문 12,322자: 입력 65,614 → 32,257자(50.8% 감소).
  - 본문 47,241자: 입력 147,160 → 83,521자(43.2% 감소).
- 각 비교는 0.1.16 대비이며 glossary 추가를 제외한 같은 조건이다.

## 제한

- 실제 새 요청의 토큰 수·정제 품질은 검증하지 않았다. 문자 감소를 청구 절감률로 해석하지 않는다.
- 로컬 빌드·설치는 기존 보류 지시를 유지한다. 실행 중 앱에는 이번 수정이 아직 적용되지 않았다.
